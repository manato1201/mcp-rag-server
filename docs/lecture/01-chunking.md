# 第 1 回 文書を断片に分ける(チャンク分割)

> 所要時間の目安: 2 時間 / 前提: 第 0 回

## この回のゴール

- 文書を**チャンク**(断片)に分ける理由と、**サイズ・オーバーラップ**の意味が分かる。
- `split_into_chunks` を 1 行ずつ読み、**文の途中で切らない**工夫を説明できる。
- チャンクの大きさを変えると検索がどう変わるか、予想できる。

## 1. なぜ分けるのか

文書を丸ごとベクトルにすると、**1 つの長い文書に、いろいろな話題が混ざって**、どの質問にも「少しずつ似ている」ベクトルになります。
また、AI に渡せる文章の量には上限があります。**質問に関係する部分だけ**を、小さな断片で取り出したい。

| 大きさ | 利点 | 欠点 |
|---|---|---|
| 小さい(100 字) | 1 つの話題に絞れる・ぴったり当たる | 文脈が足りない・断片が多くて遅い |
| 大きい(2000 字) | 文脈が揃う | 話題が混ざり、検索の精度が落ちる |
| 既定: **500 字** | 中間 | — |

## 2. オーバーラップ

境界でただ切ると、**文の途中や、話の切れ目の前後が、別の断片に分かれて**しまいます。
そこで、隣り合う断片を **100 字ぶん重ねます**(オーバーラップ)。境界の前後が、少なくとも片方の断片に、まとまって入ります。

## 3. 実際のコード

```python
# 引用: src/document_processor.py::DocumentProcessor.split_into_chunks
def split_into_chunks(self, text: str, chunk_size: int = 500, overlap: int = 100) -> List[str]:
    """
    テキストをチャンクに分割します。

    Args:
        text: 分割するテキスト
        chunk_size: チャンクサイズ（文字数）
        overlap: チャンク間のオーバーラップ（文字数）

    Returns:
        チャンクのリスト
    """
    if not text:
        return []

    chunks = []
    start = 0
    text_length = len(text)

    while start < text_length:
        end = min(start + chunk_size, text_length)

        # 文の途中で切らないように調整
        if end < text_length:
            # 次の改行または句点を探す
            next_newline = text.find("\n", end)
            next_period = text.find("。", end)

            if next_newline != -1 and (next_period == -1 or next_newline < next_period):
                end = next_newline + 1  # 改行を含める
            elif next_period != -1:
                end = next_period + 1  # 句点を含める

        chunks.append(text[start:end])
        start = end - overlap if end - overlap > start else end

        # 終了条件
        if start >= text_length:
            break

    self.logger.info(f"テキストを {len(chunks)} チャンクに分割しました")
    return chunks
```

1 行ずつ読みます。

1. `end = min(start + chunk_size, text_length)` — いったん、500 字先を終わりにする。
2. `if end < text_length:` — 文書の終わりでなければ、**文の途中かもしれない**ので調整する。
3. `next_newline` / `next_period` — `end` より後ろで、**最初の改行**と**最初の「。」**を探す。
4. 近い方(改行が先なら改行、句点が先なら句点)までを、チャンクに**含める**(`end` を延ばす)。
5. `start = end - overlap` — 次のチャンクは、**100 字戻って**始める(オーバーラップ)。
6. 戻った位置が `start` 以下なら(進まない)、`end` から始める(無限ループの防止)。

**注意**: チャンクは、`chunk_size` を**超えることがあります**(次の改行・句点まで延ばすため)。英語のように「。」の無い文章では、次の改行まで延びる。

```python
# 実行できる
from src.document_processor import DocumentProcessor

dp = DocumentProcessor()
text = "これは最初の文章です。" * 6 + "\n" + "二つ目の段落になります。" * 6
for i, c in enumerate(dp.split_into_chunks(text, chunk_size=40, overlap=10)):
    print(i, f"{len(c):3d} 字", repr(c[:10]), "…", repr(c[-6:]))
print("空の文書:", dp.split_into_chunks(""))
```

```text
# 出力
0  44 字 'これは最初の文章です' … 'の文章です。'
1  45 字 'れは最初の文章です。' … 'になります。'
2  46 字 '目の段落になります。' … 'になります。'
3  34 字 '目の段落になります。' … 'になります。'
4  10 字 '目の段落になります。' … 'になります。'
空の文書: []
```

- 長さが 40 より**大きい**チャンクがあるのは、句点・改行まで延ばしているため。
- 隣の断片の**先頭が、前の断片の末尾と重なっている**(オーバーラップ)。

## 4. 区切り文字を日本語に寄せている

分ける目印は、**改行**と**「。」**だけです。英語の「.」・「?」や、「!」は見ません。
英語の文書では、**改行まで延びる**ので、チャンクが大きくなりがちです(改良するなら、`split_into_chunks` に区切り文字を足す。[拡張のしかた](../learn/04-extend.md))。

## 確認問題

1. `chunk_size=500`、`overlap=100` のとき、隣り合うチャンクの先頭は、何字ずつずれますか(目安)。
2. チャンクが `chunk_size` を超える理由は。
3. オーバーラップを 0 にすると、何が困りますか。
4. 空の文字列を渡すと、何が返りますか。

## 解答

1. 約 400 字(500 − 100)。ただし、句点・改行まで延ばすので、実際はもう少し大きい。
2. 文の途中で切らないよう、次の改行または「。」まで、終わりを延ばすため。
3. 境界の前後の文が、別々の断片に分かれ、**質問に必要な文脈が、どちらにも不完全に**入る。
4. 空のリスト `[]`(最初の `if not text`)。

## まとめ

- 文書は、500 字ほどの断片に分ける。小さいと文脈が足りず、大きいと話題が混ざる。
- 100 字のオーバーラップで、境界の前後を、片方の断片にまとめて入れる。
- 文の途中で切らないために、次の改行・「。」まで延ばす(サイズを超えることがある)。
- 次の回は、断片を**ベクトル**にして、意味の近さを測る。
